# GSC metadata optimization backlog — 2026-10-07

> Historical, page-level Search Console snapshot. This is a prioritized copy and metadata backlog, not evidence that changing a tag alone will change rankings or CTR.

## Executive Summary

- **148 of 415 URLs** have a title longer than 60 characters, a description longer than 160 characters, or both. Together they produced **21,889 impressions** in the 90-day period, or **25.8%** of page-level impressions.
- **Five pages should be fixed first:** the JavaScript object-comparison page has a clear grammatical/template defect; the home page, coding hub, and interview-question hub have generic or overstuffed descriptions; and the Angular lifecycle page is long in both fields.
- **The recommendations below match the page's actual H1 and content coverage.** Every proposed description answers the searcher's question or gives the next action directly; it does not merely describe the page. They are editorial targets, not hard limits.
- **A separate technical fallback risk was fixed in code:** an unavailable Tradeoff detail can no longer expose indexable generic metadata. Deployment and a later Google recrawl are still required before the live SERP can reflect it.

## Resolved technical finding: generic Tradeoff detail fallback

GSC had shown a generic Tradeoff title/description for at least one valid detail URL. The normal prerender happy path already had detail-specific metadata, but a resolver failure or null result could fall through to an indexable route-level fallback.

The implementation now builds the complete SEO payload from the resolved Tradeoff scenario before component render, applies it through the title strategy during SSR/prerender, removes the old route fallback, and gives an unavailable detail a `noindex,follow` fallback. The same SEO builder is reused after hydration. Regression coverage includes the resolver failure path and raw prerendered HTML for the complete Tradeoff catalog.

This protects future crawls after deployment. It does not immediately replace a cached Google title or snippet.

### Implemented prerequisite: preserve the targeted answer-first Trivia metadata

The Trivia SEO utility previously accepted authored metadata only when it matched a narrow `hasRetargetedIntent()` heuristic. That could replace valid answer-first copy such as `Use href …`, `Use constructor …`, `Use switchMap …`, or `Use props …` with the generic “quick interview answer / common mistakes” fallback during SSR/prerender.

This release now also recognizes the two direct-answer forms used by the six applied entries: descriptions beginning with `Use …` and the `In …, call/use …` form. It retains the docs-style exclusion and the deterministic fallback for missing or invalid metadata, so this is intentionally narrower than opening the gate for all authored copy. Regression cases cover object comparison, lifecycle, `href`, RxJS operators, `forRoot`/`forChild`, and Vue `provide`/`inject`.

During verification, SSR was also found to prefer a stale working-directory asset before the browser asset paired with the active server build. The server asset reader now prioritizes the active build's browser assets, preventing an older `prime-ssr-inline` artifact from supplying stale Trivia metadata. The final 615-route production prerender asserted the exact title, description, Open Graph, Twitter, canonical, robots, and `og:url` values for all 11 entries.

### Live-crawl caveat

The GSC Wizard on-page crawler received HTTP 429 for all 11 URLs during this review. That does **not** prove Googlebot is blocked—the pages have GSC impressions and current Google results—but it means this crawler could not independently confirm live HTML this pass. Verify the WAF/bot policy with server logs or Google URL Inspection before treating bot access as healthy.

## Trivia metadata-gate follow-up

The direct-answer repair is implemented, but the wider policy remains deliberately bounded: an authored description must still match a retargeted-intent signal or one of the two answer-first forms, and it must not be docs-style copy, before it replaces the generic interview-answer template. This keeps the release bounded while allowing the direct-answer copy selected in this audit.

Recommended separate follow-up:

1. Decide whether all valid, topic-specific authored descriptions should win even without a retargeted-intent or answer-first signal.
2. Keep a deterministic fallback only for questions without usable authored metadata.
3. If broadening the policy, add representative fallback and docs-style cases before running the metadata audit after a prerender build.

### Resolution — 2026-10-09

The follow-up was decided and implemented: authored `seo.title` and `seo.description` now win whenever they are present, are not documentation-flavored, and are long enough to describe the page (two words for titles, six for descriptions). The deterministic interview templates remain only for missing or rejected copy. A full prerender after the change showed zero template descriptions on the 261 indexable trivia pages (previously 99, 20 of them with broken grammar) and 64 titles returned to their authored form. The 29 longest authored titles with Search Console impressions were shortened to 60 characters or fewer in the same release.

## Suggested rollout order

1. Deploy, request recrawls for the five P1 URLs, and compare GSC page-level impressions, CTR, and Google-selected titles/descriptions after a sufficient recrawl window.
2. Re-run the same 90-day query after 4–8 weeks. Keep a separate pre/post record because position, query mix, seasonality, and Google snippet rewrites can all move independently of metadata.

## Caveats and next checks

- Search Console page-level CTR does not prove that metadata length caused low CTR; several candidates rank mainly in positions 15–32.
- Google can rewrite titles and descriptions, as the Google-display column demonstrates. The recommended text is a controllable input rather than a guaranteed SERP snippet.
- The Google snapshot is a `site:` query with personalization disabled, English UI, and a Türkiye device location. Natural-language queries, country, device width, and later recrawls can produce a different title or snippet.
- Character counts are editorial review signals, not strict pixel-width limits.
- The proposed copy is intentionally English because the indexed pages and current metadata are English.
- The 11 title/description pairs in this backlog are now applied in source. Deployment and a later Google recrawl are still required for live SERP changes; the Tradeoff resolver/fallback fix remains a separate completed implementation.
